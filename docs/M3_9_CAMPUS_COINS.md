# M3.9：校园金币、任务经济与午餐快递

> 独立的游戏内虚拟货币，**与真实金钱无关，不包含付费购买/真实支付**。继续沿用非官方、虚构的 UTown 游戏定位。全系统离线，金币数据保存在单独文件中，不修改已有账号、XP、校园任务或 NPC 的存档。

## 如何玩

| 按键 | 功能 |
|---|---|
| **Z** | 靠近道路上的闪光金币后拾取 |
| **N** | 在 Fine Food（Town Plaza）领取午餐订单；抵达 Town Green 后按 N 交付 |
| **O** | 打开／关闭金币商店（鼠标点击购买） |
| F7 | 原有拍照模式，金币 HUD 与地面金币同步隐藏 |

**顶部金色 C 图标** 显示当前金币余额、累计收入和任务提示。地图上的金币是旋转的金色圆牌，有可读的 C 字样，不需要外部图片素材。

## 金币来源

- **校园导览**：每个独立完成的 UTown Explorer 路标 +12 C
- **Field Notes**：每张笔记首次发现 +14 C
- **室内活动**：首次访问校园活动 +17 C
- **老师作业**：每个虚构教授的一次性互动 +10 C
- **Campus Sprint**：首次完赛 +25 C；达到银/金成绩分别额外 +12/+18 C
- **搞笑 NPC 对决**：每次学生休息 +6 C；附带 32% 概率在现有道路附近额外随机出现金币
- **随机掉落**：约每 13 秒尝试在现有示意步行道上刷出随机金币（1 C / 3 C / 8 C）。金币 65 秒后消失。场景上限 12 枚，不会无限增长
- **可重复午餐快递**：从 Fine Food 到 Town Green，100 秒内完成 +38 C；在剩余至少 50 秒时完成另加 +15 C。完成后有短暂订单冷却，不依赖真实地点定位或付款

任务首次奖励使用**独立的唯一领取账本**。重复做完已有导览或加载旧存档，不会再次支付同一奖励。午餐快递是特意设计的可重复收入来源；新一轮学生对决仍可获得金币。

## 商店与道具

- **Lucky Badge：35 C**：接下来的 5 枚随机金币奖励双倍，效果期间不可重复购买
- **Lunch Time Pass：28 C**：下一次接单时增加 35 秒，最多保存 3 张
- **Golden Tip Pass：60 C**：下一次成功交付的快递金币奖励翻倍，最多保存 3 张

商店中的购买会即时扣款并记录效果；余额不足时禁止购买。换装、照片、骑行、接驳车、室内交互仍遵循此前独立系统。

## 性能与进程隔离

- 新脚本：`godot/scripts/utown_coins.gd`，主场景末尾新增 `Coins` 节点（场景资源编号 15），**不覆盖此前 1–14 的场景资源**。
- **12 枚金币固定对象池**：全部共享一个 CylinderMesh、一个 StandardMaterial3D。刷出和消失时仅改变节点状态/可见性，不逐次创建、销毁网格。
- 地图掉落位置从**既有 walkways** 中一次性索引，完全不写入新的经纬度；每 0.35 秒检查既有任务进度，HUD 最快每 0.25 秒刷新。
- 拾取不加入物理碰撞，以玩家与金币的水平距离判断；不会卡住现有路径。
- `user://nus3d_coins.cfg` 包含余额、累计收入、领取账本和商店剩余效果；**不写入其他模块原有 ConfigFile**。随机未拾取金币与正在进行的短时快递不跨会话保存，避免离线时间判定混乱。
- F7 会隐藏金币 UI、世界金币；商店会释放鼠标用于点击，关闭后按原状态恢复鼠标捕获。

## 验证

在 Godot 4.4.1+ 导入项目，先运行此前的场景与地图测试，再运行：

```bash
godot --headless --path godot --script res://tests/coins_smoke_test.gd
```

测试覆盖：余额与商店扣款、图标存在、共享网格和固定数量对象池、单次任务的不可重复领奖、拾取双倍增益、NPC 对决随机掉落触发、食阁领取与草坪交付、双倍小费、延长时间、F7 隐藏、存档读写与重启后防重复领取。

目前的资源复用能**控制新增对象数与内存增长风险**，但真实 RAM/VRAM 绝对占用和 Windows 帧率仍需目标机器实测，不能从逻辑回归推导具体节省百分比。
